## Review

**Acceptance.**
- (a) `Context::library` returns no target when `explicit.is_none() && !self.package.auto("lib")`.
  The first case of the new test (autolib off, `src/lib.rs`, `src/main.rs`, no `[lib]`)
  asserts that only the binary is found. Before the fix this fixture would also yield the
  library, so the assertion is a real negative fixture.
- (b) The second case adds `[lib] name = "demo"` under the same flag and asserts that the
  library is kept. The explicit path, the missing-file error and the origin handling are
  untouched, because the guard only fires without `[lib]`.
- (c) When `autolib` is true the guard is inert, so the code path is byte-for-byte the old
  one. The third case and the existing default-path tests confirm this.
- (d) `binaries` and `examples_like` (test, bench and example) are untouched. Case one shows
  `src/main.rs` is still inferred under `autolib = false`, and the existing autodiscovery and
  default-path tests pass.

**Same rule as the reference helper.** `library_target_name` (`manifest.rs:931-936`) returns
the `[lib]` name when `[lib]` exists. Otherwise it returns nothing when
`!package.auto("lib")`, and otherwise it checks `src/lib.rs`. Discovery now applies the same
precedence through the same `PackageDecl::auto("lib")` predicate, which is fed by the one
`("autolib", "lib")` entry in the manifest parser. Discovery and the reference helper now
agree for every `autolib` and `[lib]` combination. The only remaining difference is
deliberate and older than this change: the helper names an explicit library without
checking its file (registry archives may omit files), while discovery refuses a missing
explicit root.

**Callers and wiring.** `Context::library` has one caller, `derive_targets`
(`target.rs:509`), which `Workspace::load` reaches (`workspace.rs:350`). So every workspace
load, and through it the census target configuration, gets the new rule. There is no
duplicate or dark path.

**Failure paths.** No error path changed. The new branch skips inference; it does not hide
a failure. An explicit `[lib]` with a missing file is still a typed `MissingFile` error.

**Test value.**
- The new test protects the named behaviour. It pairs the negative fixture with a valid
  neighbour under the same flag (explicit `[lib]`) and with the default-flag neighbour.
- It asserts observable targets through the public `Workspace::load`, so it does not mirror
  the implementation.

**Docs and assessment.**

## Findings

1. **OPTIONAL**: the rule "no `[lib]` and `autolib = false` means no library" is written out
   twice, in `target.rs:291` and `manifest.rs:934`. Both evaluate `package.auto("lib")`, so
   they agree today. A shared predicate on `Manifest`, for example "infers a library", would
   keep them from drifting. The contract does not require it.
2. **OPTIONAL**: AGENTS.md section 6 says to extend an existing behavioural case first. The
   autolib-off case could have been folded into
   `autodiscovery_flags_turn_inferred_targets_off_but_explicit_tables_are_still_found`. The
   new test's default-flag case also partly overlaps the existing default-path test. Both
   are small.
3. **OPTIONAL**: older than this change: the rustdoc of `library_target_name`
   (`manifest.rs:883-887`) says a package without `[lib]` "has a library only when
   `src/lib.rs` exists". It does not mention the `autolib = false` exception that the
   function implements and the capability document states.
