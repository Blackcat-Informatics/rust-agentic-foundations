`151-160`: **🚀 Performance & Scalability** | **🔵 Trivial** | **⚡ Quick win**

**Cache source owners per byte instead of scanning the file for each occurrence.**

`source_owners` calls `workspace.item_at`, which filters every item of the file. It then calls `same_source` for each candidate. Several paths reach this function:
- `matches` calls it for each path occurrence, and once more for each compiled pattern at that occurrence (`visit.rs` line 139 onward).
- `constant` calls it for every pattern binding through `Paths::bind`.
- `constant` also calls it for every `PatIdent` when a `path` pattern exists.

The total cost grows with occurrences × items in the file × patterns. The `MatchLimits` step grant does not charge this work, so the limit does not bound the time on large generated files.

Compute the owners once per file, for example from a sorted span index. Alternatively, memoize them by `site.byte` in the `Paths` visitor and pass the result into `matches` and `constant`.

Based on learnings: "flag code that performs a linear scan over the full list for each item, causing O(n*m) behavior on large inputs. Prefer precomputing an index".
