## Reuse of `review-stale` for a findings verdict (decision)

A distinct kind is **not required**. `Finding::KINDS` and `ObligationKind::ALL` are closed lists,
but nothing in the vocabulary forces one kind per cause. Nothing consumes `review-stale`
differently from its siblings: `strict.rs` maps every non-missing review obligation to it, and the
debt record does not hold review findings, which are added after `debt::judge`. The only document
that defines the kind (the reconcile obligation table) was updated to name both causes. The case
with findings and stale inputs together would need one kind anyway. The message and the reconcile
detail both name the failing condition ("has the verdict findings", "has changed inputs", or both),
so the text is honest. The name "stale" is loose for a review that is current and has findings,
but it does not mislead about what to do next, because the text says it. Leaving the kind as is
is acceptable.
