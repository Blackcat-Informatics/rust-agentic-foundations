# Plan: issue 21, replace wall-clock assertions in tests with counts

## Issue summary
Time-based testing is forbidden (CLAUDE.md). Tests of `raf-okf`, `raf-workplan` and `cargo-workplan` still assert or bound elapsed time, wait on real timers, or carry wall-clock budgets. Convert each to an operation count, an allocation count, a deterministic signal or a scripted/virtual clock, keeping the guarantee each test protects; every converted test fails on a mutant that removes the bound it protects; `make check` and hosted CI pass. The raf-source part of the issue (its comment) was delivered by the merged source-index change (work tallies, counting tree, clock-free tests, gate `time_in_raf_source`).

## Standing goals and decisions
CLAUDE.md: no timing runs (instruction counts via `perf stat -e instructions:u` allowed), Linux primary and other systems minimal effort, no issue/PR numbers or process wording in committed files, hooks on, capability documents through the lifecycle (bound-test renames update bindings, Verification text, assessments; `make docs-sync`). Owner decisions on record: "Convert timing tests first" (raf-source, done); macOS is minimal effort.

## Design source
`clock-inventory.md` in this directory is the exhaustive inventory (sites classified A/B/C/D/E), the conversion per site, the runner clock seam, bindings that change, the gate extension and the commit order. This plan adopts it with the dispositions below.

## Dispositions of the inventory's open decisions
* Coverage product (inventory 6): pin it exactly (`ExclusionTests == entries x exclusions`, linear in each dimension with the other fixed) and state the product in the Verification text; indexing the exclusions is a production change outside this issue and is declined here with the visible cost (coverage judging stays entries x exclusions; a follow-up issue is filed at the end of this change).
* Uncounted loops: accept the limit (counts catch regressions on the counted path; a brand-new uncounted loop is not caught), as the raf-source conversion did; state it in the Verification text of okf-profile.
* Never-ending real-cargo tests (R5): P1 (move into unit tests behind the stepped clock with a pid FIFO; the evidence record `gate-kills-a-test-past-its-timeout` is recorded again and its contract assessment re-assessed).
* Linux-only checks (`/proc/<pid>/status` `ShdPnd`, `waitid`) assert only on Linux; other systems keep the error assertions (minimal effort).
* Budgets (R6): dropped; the runner's own limits and CI `timeout-minutes` are the watchdogs.
* Acceptance grep widened: the issue's `grep -rn "Instant::now"` is replaced by the extended repository gate (clock readings, sleeps and timeout waits in tests and library code; `Duration`, `elapsed`, `timeout` stay allowed as the runner's feature and as scripted data).

# Revision 1 (integrates reviews/plan-{completeness,constraints,design,enhancement,adversary}.md; supersedes the table, tasks and declines above where they differ)

## Corrections and additions
* **Inventory additions.** The workspace-root `tests/docs_contract.rs` (~lines 1315-1319 a scratch name from `SystemTime`; ~1359-1361 a test failed after `recv_timeout(10 s)`) is converted in Task 8 (pid+counter name; the deadline replaced by a blocking join with no clock) and the root `tests/` directory joins the gate. `crates/raf-okf/tests/bounds.rs` (a counting `GlobalAlloc`) and `alloc_bound.rs` (`cap`) exist: allocation counts bound memory, not the three scan regressions of `validate_cost.rs` (a scan allocates nothing per step), which is why operation counters are added.
* **Evidence ordering (C1).** Task 4 (the seam) re-assesses only the assessments its code change makes stale; the evidence record `gate-kills-a-test-past-its-timeout` is recorded again only in Task 7, against the clock-free subject. The inventory's P2 (keep a real 5 s timer) is struck; P1 only. No agent runs the old real-timer subject.
* **Per-invocation clock (design B2).** `Executor::test` runs a list pass and then a run pass through one runner. The unit-test runner wrapper chooses the clock per invocation: the real `WallClock` for `--list` (it finishes), the Stepped clock for the run. The assertions: the reason "ran 5.0 s of its 5 s limit", `Ended::TimedOut`, the run's own `elapsed == 5 s`, `wall >= 5 s`, and that the test binary's pid got SIGKILL.
* **Kill detection (enhancement 3, design advisories).** `pidfd_open` (rustix `process` feature, already a dependency) is taken on the grandchild BEFORE the kill is requested (the Stepped gate captures `/proc/<g>/stat` state, `pgrp` and `starttime` first); after `kill_process_group` returns, the check is a three-way decision: state `T` without a pending SIGKILL fails fast; pending SIGKILL, `Z`/`X` or gone passes; otherwise block on `poll(pidfd)` (a wait on an event, not a clock). Linux only (CLAUDE.md platform rule); other systems keep the error assertions.
* **Never-ending scripts (constraints C5).** The blocking is a read of a FIFO the test holds open (not `kill -STOP $$`: an orphaned group makes a stopped grandchild receive SIGHUP+SIGCONT and test 5 racy). FIFOs are made with `rustix::fs::mknodat` or the script's own `mkfifo` by absolute path (test 4 runs with an empty `PATH`); no `libc`/`nix`; `PATH` is set only on the child `Command` (`std::env::set_var` is unsafe in edition 2024). A script that dies before writing the FIFO is a hang; the test opens the FIFO with `O_NONBLOCK` and polls the pidfd too so it fails instead.
* **Ceilings on both test clocks (adversary F1).** `Frozen` also counts every `pause` and panics at a ceiling (tests 6 and 7 can no longer hang on a mutant: the mutant that never lets the loop finish hits the pause ceiling); `Stepped` counts every pause, not only advancing ones. A hang is a failure to fail: no test relies on a hang to detect a mutant.
* **Exact counts, not one-dimensional growth (design B1).** The raf-okf and raf-workplan counted tests pin exact counts where the count is a function of the input (`AffectsEntries == n`, `LimitLookups == n`, `ClaimChecks == total slugs`), or scale BOTH dimensions together at units 1/2/3 with the idiom `one > 0, three + one <= 2*two`; a product-shaped mutant (A*B) fails the scaled-both test.
* **Documented-regression mutants (adversary F2).** Besides counted-path mutants, each raf-okf probe has the mutant the test documents: `check_affects` with `changes.iter().any(..)` per entry, `visible_content` scanning every block per section, limits resolved by `values.iter().find(..)` per limit. To make those fail without counting newtypes, the raf-okf tests run on inputs where the scan would add counted steps: the counted loops are routed through the same accessor (`add` inside the shared lookup helper `contains_change`/`find_measure` that the production code uses), so a regression that bypasses the helper is caught by `one > 0` failing... if the helper is bypassed the tally stays at 0 and `one > 0` fails. Each such mutant is run and recorded.
* **Inputs without a bound (completeness 3).** `assessments.rs` 12,000-line Contract: counted by `ContractLines`/`NamingLookups`; `rationale.rs` 100,000 headings counted (`HeadingsScanned`), and the unterminated-fence cost is raf-okf's parser cost (counted in raf-okf's `FenceScans` hook in Task 1; raf-workplan tests assert the page is judged and the fence finding present, without a time).
* **Coverage mutants.** `exclusion_for` called once per path instead of once per entry; a second call when the entry is not covered; both fail the pinned product.
* **Budgets (adversary F7).** A wall-clock budget is a timing assertion, which the rule forbids; its removal is required by the rule, not a cut. It never caught a hang (checked after the run returned). The per-fixture cost bound it implied is given up: stated in the PR. A counting `$CARGO` wrapper is declined (cost: a wrapper binary or script per fixture, new test infrastructure, for a bound nobody asked for).
* **Windows (adversary F6).** The never-ending cargo tests become Unix-only unit tests; Windows keeps the error assertions and the FakeRunner mapping tests; the Windows CI job comments and the `tests/bound.rs` module doc are corrected (CLAUDE.md: other systems minimal effort; recorded).
* **Kept watchdog (C4).** `both_streams_are_drained_at_once` moves under the frozen clock with the pause ceiling as its deadlock detector; no 30 s limit remains.
* **Assessments (C2).** Each task lists the stale assessments after its code change (`workplan assess --list`) and re-assesses all of them after re-reading each section; the hook enforces this.
* **Validation (C3).** Until Task 8 lands, validation uses exact test filters (never a whole-crate run that reaches an unconverted timing test), mutants are never caught by a `timeout` wrapper, and every agent is told the no-timing rule.
* **Enhancement dispositions.** Taken: `pidfd` (3), compiler-resolved ban through `clippy.toml` `disallowed-types`/`disallowed-methods` for `Instant`, `SystemTime`, `std::thread::sleep` and the lexical gate deriving its directories from `crates/*` (4), the allocation-counter note (5). Declined with cost: one shared cost-model crate replacing three copies of `work.rs` (new workspace crate, publishing surface and dependency for a test-only helper; raf-source set the copy precedent), the event-driven wait that removes the pause schedule from production (changes the production loop's structure and its documented schedule; larger than this issue), counting `Counting<Runner>` decorators across crates (needs the shared crate).
* **Declined coverage index (C6).** A separate proposal, filed as an issue at the end of this change; no committed text says "follow-up".
* **Conventions (C7).** SPDX headers on new files; both doc spots of the gate rename (module doc lines 19-21 and 25); the issue's literal `grep -rn "Instant::now" crates/*/tests crates/*/src` is also run and empty; `Closes #21` only in the PR body.

# Revision 2 (answers the final review; supersedes Revision 1 where they differ)

* **B1 gate self-reference.** The lexical gate has two exempt files, both asserted to be tracked: `crates/raf-workplan/src/exec/clock.rs` (the one clock reading) and `tests/repo_gates.rs` (it names the words in its own word table and fixtures; the gate asserts the file defines the table). Everything else under the three crates and the root `tests/` is judged.
* **B2 clippy ban.** `clippy.toml` `disallowed-types`/`disallowed-methods` for `Instant`, `SystemTime`, `std::thread::sleep` run under `--workspace --all-targets -D warnings`. Two allows are needed and each carries a reason (workspace rule): `exec/clock.rs` (the one production reading) and `crates/raf-source/examples/registry_scan.rs` (an example binary that still reads the clock, its conversion is its own change); the allow in the example names that.
* **B3 kill detection, no hang.** The never-ending subject blocks on a read of a hold FIFO (`read < hold`, state S). Protocol: the script writes its pid to the pid FIFO, then blocks on the hold FIFO; the Stepped clock captures `/proc/<g>/stat` (state, `pgrp`, `starttime`) and takes a `pidfd_open` before the kill is requested; after the run returns, the test releases the hold (writes a byte to the hold FIFO opened `O_NONBLOCK`) and the script then writes a marker file and exits. Then `poll(pidfd)` always returns: a killed grandchild never wrote the marker (assert absent), a surviving one (mutant: `kill_group` dropped) wrote it and exited (assert fails). Same protocol replaces `park()` in the R5 P1 fixtures. No wait can hang; every step is an event.
* **B4 raf-okf mutants, corrected.** No shared counted helper. For `check_affects` (one lookup at `mod.rs:~636`) and the records limit index (one lookup at `records.rs:~597`) the index-building counters read 0 when the documented regression deletes the index (`one > 0` fails) and the lookup site is counted; `visible_content` has no lookup (a `partition_point` and a `break` loop at `body_rules.rs:50-55`): its documented regression is the counted-path mutant (`let first = 0` or remove the `break`), caught by scaling sections and blocks together. The R3 tests missing mutants: test 4 (empty `PATH`): `terminate` spawning an external `kill` program fails; test 6: `>` instead of `>=` at the overflow comparison fails either the 1000-byte pass or the 1001-byte refusal. The paragraph in Revision 1 about routing production code through a shared helper is withdrawn.
* **B5 acceptance grep.** The literal `grep -rn "Instant::now" crates/*/tests crates/*/src` is run and its only hit is `exec/clock.rs` (a reading, as the issue words it, not an assertion); the extended gate asserts that nothing else reads a clock.
* **B6 root `docs_contract.rs` FIFO test.** The scratch name uses pid plus counter; the FIFO-blocking test is rewritten with `/dev/null` and a directory as the non-regular subjects (asserting the typed refusal, no open of a FIFO); the loss (a loader that would block on a FIFO is not detected without a timer) is stated in the PR.
* **B7 enhancement dispositions.** 6 taken (nonces use `tests/support/disk.rs::Scratch`; the `$CARGO` wrapper option is dropped); 7 declined with cost (a public `Clock` trait with `SystemRunner::with_clock` widens the public API of a delivered capability for a test seam; the seam stays private and the cargo tests are lib unit tests); 8 taken (the follow-up issue and the Verification text say the product is inherent to the contract, since `exclusion_for` marks `matched` for unused-exclusion reporting, and an index must return all matches; `EntriesJudged == entries` pinned); 9 taken (no "105 looks" pin in the kill test: `elapsed == 2 s` exactly plus a look ceiling; the schedule is asserted in the `next_pause` pure test only); 10 taken (`Frozen` has a look ceiling); 11 taken (FIFOs via `rustix::fs::mknodat`, the rustix `fs` and `event` features added to the dev-dependency feature list (`crates/raf-workplan/Cargo.toml:22` lists only `process, std`): this is an existing crate's feature, no new dependency; the drop guard SIGKILLs the recorded group as well as the pids); 12 taken (Task 1 removes only the raf-okf clause of the release-probe reasons; `make test-release` and the CI `test-release` job keep the raf-source reason).

# Revision 3 (answers the recheck; one defect and three advisories)
* **B3' hold release.** The test opens the hold FIFO `O_RDWR` BEFORE spawning the subject and keeps the descriptor; the release is a plain `write` of one byte on it (no `O_NONBLOCK` open of a write end, which fails with `ENXIO` when no reader exists and can strand a subject between its pid write and its `open`). The pid FIFO is read the same way (opened `O_RDWR` before the spawn). The R5 P1 fixtures use the same guarantee.
* Test 6 mutant direction: the production comparison is `length > bound` (`system.rs:~191`); the mutant is `>=`, which refuses a 1000-byte output.
* The `ContractLines` and `HeadingsScanned` counters belong to Task 2 (not Task 1); their mutants: re-scan the Contract from its first line for each line (`ContractLines` becomes quadratic in the scaled-both test), and re-scan the headings for each heading (`HeadingsScanned`). `FenceScans` (Task 1) mutant: restart the fence scan from the start of the page for each line.
* rustix features: `fs` and `event` are added on a new `[target.'cfg(unix)'.dev-dependencies]` line for rustix (the existing `[target.'cfg(unix)'.dependencies]` line stays `process, std`, so the production feature set does not grow; Cargo unifies the features for test builds only).
