## Findings

### Q-1 (Medium) Goldens are self-referential and the count bound is a lower bound
`crates/raf-okf/tests/render.rs:75-86`. The "goldens" are the repository's own tracked docs, and the
documents are edited together with the renderer in this very PR. A renderer that changes canonical
form (for example drops a trailing comment) together with a re-render of the docs would still pass. Nothing is
regenerated by the test itself (no bless mode), which is good, but the anchor is only
`render(parse(x)) == x`. `paths.len() > 20` is a weak floor: currently 42 files (21 Capability, 19 Change,
2 Architecture); deleting 20 documents, or `git ls-files` returning a pathspec subset, still passes.
Also `git ls-files` failing in a source tarball or shallow export is an assertion failure, not a skip (acceptable, hard fail).
Test to add: `assert_eq!(count_by_type, ...)` is brittle, so instead assert per directory `>= 1` for each of
`docs/capabilities`, `docs/architecture`, `work/changes` and each `DocType` appears at least once, and add 3-4
committed fixture files under `crates/raf-okf/tests/fixtures/*.md` (one per DocType, with comments, CRLF,
flow and block tags) compared byte-for-byte. These pin the format independently of the docs.

### Q-2 (Low) Only Architecture/Capability/Change documents are exercised by the file-based golden
No golden carries a BOM, NUL, non-UTF-8, or a lone `\r`. Probe: a leading BOM is refused with "does not start with a `---` fence line" and a NUL in the body round-trips; but no test pins either.
Add to refusals.rs: `a_leading_bom_is_refused_at_line_1_column_1` (assert `ErrorKind` and position for
`"\u{feff}---\ntype: Architecture\n---\n"`), and to render.rs `a_nul_in_the_body_round_trips`. Also `"--- \n"` (fence with trailing space) is refused; pin it.

### Q-3 (Medium) Unknown-key fixture exists for Architecture only (OV-2)
`crates/raf-okf/tests/profile.rs:170-182`; the Verification bullet (docs/capabilities/okf-profile.md:307) says "per type ... each extra key". Probe shows a Capability with `extra: 1` is accepted by `Document::parse` (correct: the rule lives in the profile), but no test asserts the profile rejects it for Capability or Change, nor inside `bindings` or `items[]` (nested unknown keys).
Test to add, next to `the_key_resource_has_its_own_rule_on_every_type`:
`for t in DocType::ALL { text = type_block(t) + "extra: 1\n"; assert_hit(&violations, &key("extra"), &Rule::UnknownKey{key:"extra".into()}) }`
plus nested cases `bindings:\n  code: []\n  tests: []\n  examples: []\n  extra: []` and a Change item with an extra field, asserting the rule and position (or document in the capability that nested keys are not checked, if so).
Alternative: reword the bullet to "for Architecture".

### Q-4 (Medium) No test drives an over-cap or at-cap `.rs` through `Workspace::load` (SV-6)
`crates/raf-source/tests/read_cap.rs:20-61` calls `Tree::read` only. Probe confirms behaviour:
8 MiB+1 `src/lib.rs` is refused with "src/lib.rs is larger than the limit of 8388608 bytes (reached by manifest key `lib.path`)"; an exactly 8 MiB file loads. If `modtree.rs:189` stopped passing `max_file_bytes` to `Tree::read` (for example passed `u64::MAX`), every existing test would still pass. Also `LoadOptions::max_file_bytes` lowered via `load_with` for a `.rs` file is untested (only manifests).
Test to add in module_tree.rs (or read_cap.rs):
`a_source_file_of_exactly_the_cap_loads_and_one_byte_more_is_refused_naming_it`: `//` + `"a".repeat(cap-3)` + `\n` loads at default; `+1` yields `LoadErrorKind::Tree(TreeError::TooLarge{..})` with `error.file == "src/lib.rs"` and the string containing the file. Add a second case with `load_with(.. max_file_bytes: 100)` on a 101-byte `mod`-reached file (child file, not only the target root). Use `#[test]` in release-friendly form (8 MiB comment is cheap, probe ran in 0.34 s).

### Q-5 (Low) `LoadErrorKind::Spawn` is only constructed by hand (SC-19b)
`crates/raf-source/src/error.rs:511-513`. Provoking a spawn failure portably is hard, so this is acceptable if acknowledged. If kept, make the intent explicit: add a doc comment on the unit test saying the path is unreachable in CI, or provoke it on Linux in a child harness with `setrlimit(RLIMIT_NPROC)`/`RLIMIT_AS` (the repo already has `tests/support/child.rs`) and assert `Spawn`. Without it the `map_err` at parse.rs:62 could be replaced with `unwrap` and no test would notice.

### Q-6 (Low) `missing_docs = "deny"` is not asserted anywhere as a value
`Cargo.toml:41`; repo_gates only checks that each member inherits and that fuzz equals root. If the root were relaxed to `warn`, the fuzz equality test and inheritance test still pass; only `make check` clippy `-D warnings` might catch it, indirectly. Add `lints_the_root_denies_missing_docs`: parse root `[workspace.lints.rust]` and assert `missing_docs == "deny"`.
A compile-fail style test is not needed.

### Q-7 (Low) Non-UTF-8, BOM and CRLF `.rs` sources through `Workspace::load`
Tree-level non-UTF-8 is covered (disk_tree_containment.rs:241) but the load-level error for a non-UTF-8 module file is not (a `mod` target that is invalid UTF-8 should give a typed error naming the declaring file and line). BOM and CRLF sources load (probe) but no test pins that facts' `line` numbers are the same for LF and CRLF versions of one file, nor that a BOM does not shift column/line. Add `crlf_and_lf_give_equal_facts_apart_from_nothing` and `a_bom_prefixed_source_loads` to module_tree.rs, asserting `line` of items equals across both variants. Add an on-disk non-UTF-8 `mod` fixture to workspace_containment.rs (unix-only is fine).

### Q-8 (Info) Positive observations (no action)
- Boundary pairs (cap, cap+1; 128/129; 1 MiB, +1) are asserted on both sides throughout.
- Cyclic mods (module_tree.rs:388), import cycles (use_resolution.rs:214), mutual `super::*` globs (111), cfg twins (312, 329), duplicate keys at every level (refusals.rs:129), shared helper dirs (discovery_targets.rs:571) are covered.
- Only one `#[ignore]`, and it is the corpus writer; `corpus_replay` replays committed files and does not regenerate them.
- Unix-only containment suites are `#![cfg(unix)]`, documented; Windows/macOS are only cross-checked by `cargo check`.
