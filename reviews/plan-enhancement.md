## Items

### TRANSFORMATION

1. **Define the self-gate as the re-completion invariant, not as "run `Gate`".** The issue's "`tests/self_workplan.rs` runs `raf_workplan::Gate`" is the static shadow of the concept the workplan is built on: *this repository stays a fixed point of its own completion gate*, meaning every delivered capability would pass `change complete` again today. `Gate::check` is only the cheap subset of that. What it provably does not cover, and nothing else in `make check` covers after a change has been completed and merged:
   - `assessment-stale` / `assessment-rejected`: these are obligations (`obligation.rs` `ObligationKind`, `is_static() == true`), emitted only by `reconcile`/`complete` for a change's `affects`. They are not in `finding.rs` `ALL_KINDS`, so `Gate::check` never reports them. The repository carries 56 assessment records in `work/assessments/`; any later edit to an assessed section or to a bound symbol silently stales them. `Workplan::list_assessments` ("Nothing is written and nothing is started") already answers the question for the whole repository, so the static self-gate can assert every record is current and accepted at cost S.
   - `claim-unsupported`: also a static obligation, not a finding. `Workplan::evidence_claims` plus the record values give the whole-repository answer at cost S.
   - Proof of run for the bindings: `cargo test --workspace` runs tests but it does not prove the bound names ran (an `#[ignore]`d bound test passes both the static gate and `cargo test`), does not run `example` targets at all (`raf_workplan::example_crate::docs_sync` is bound by `workplan-generated-docs`; a runtime failure there passes every current gate), and does not refuse `no_run`/`compile_fail` doc tests. `verify` (lifecycle/verification.rs) over every capability is exactly this proof.

   Proposed shape: a static layer in `tests/self_workplan.rs` (findings empty, assessments current and accepted, claims supported) run by the hook and `make test`; and a dynamic layer, `cargo workplan verify` over the repository, as its own CI job. Cost: static S–M; dynamic L (the capability documents bind roughly 1,400 test and example items and `verify` runs two `cargo` passes per binding, so the job needs its own long timeout; a batched run pass per target, which libtest's multiple positional `--exact` filters permit, would be the library improvement that makes it cheap, and is the natural follow-on when the census self-gate arrives). Payoff: decisive. This is the only form of the gate under which "every M1 capability is delivered with resolved bindings and a generated verification matrix" remains true after merge rather than at the moment of the PR. Changes Task 1 ("Create the test file ... fixture test that the gate fails on a planted fault") and the contract rows "`tests/self_workplan.rs` runs `raf_workplan::Gate` on this repo" and "self-workplan gate passes in CI".

2. **Make the self-gate a bound, documented behaviour of the tool.** Bind the tests of `tests/self_workplan.rs` as `rust_agentic_foundations::test_crate::self_workplan::<name>` in the `tests:` list of `workplan-complete-gate` (or `workplan-document-model`), and let its Usage name this repository's gate as the canonical dev-dependency use (gate.rs's own doc example is a hypothetical `tests/workplan.rs`). The root package is already in the source index (`repository_bindings_resolve_in_the_source_index` lists `rust-agentic-foundations`), so the binding resolves today. Payoff: the dogfood gate lands on a generated verification matrix, a renamed self-gate test becomes `binding-unresolved`, and the affected assessments go stale and must be re-run with `assess`, which is the tool exercising itself on this very change (R17, "with the tool itself"). Cost M (docs sync, two or three assessments). Changes Task 1 and the contract row "every M1 change record completed with the tool".

### LEVERAGE

3. **Pass the index listing to the gate instead of relying on the no-`.git` fallback.** `Gate` documents that, in a directory git says is not a work tree, "every file under the directory stands for a tracked path", which "weakens the rule that a link to an untracked file is broken". Under the hook the snapshot is such a directory, and worse, if `TMPDIR` lies inside some other git work tree the gate lists *that* repository's index. `tests/support/mod.rs::tracked_paths()` already lists the package's index (that is why `docs_contract` is immune); feed it to `Gate::tracked_paths` (a `PathBuf` to `RelPath` conversion). Cost S. Payoff: the self-gate judges the same file set in the working tree, the hook snapshot and CI, with no environment-dependent path. Changes Task 1 ("uses `tests/support/mod.rs` `gate_root()`").

Replace the list with the invariant "every capability whose state is `delivered` holds a `verification-matrix` block with at least one test row", computed from `Opened::workplan().capabilities()`. If a missing (as opposed to stale) matrix in a delivered capability is not already a finding, add it to `Workplan::check` as a rule with its negative fixture, so every consumer gets it. Naming the set "M1" in a committed test is also development-process wording in the sense of AGENTS.md section 7 even though `refs.rs` does not pattern-match it; the derived form avoids it. Cost S (M if the rule is added). Changes the contract row for R12/R15 and Task 1.
