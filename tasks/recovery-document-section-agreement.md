## Document model

- **`cap:workplan-document-model#purpose`: accepted.** The distinction between permanent current capability and temporary change is implemented by the separate typed documents, stable capability identities and change lifecycle. The actual lifecycle fixtures preserve the capability path and identity while completing/deleting the temporary record; Git retention is separately exercised by the real completion fixture. This is an account of the model's purpose, not a claim that the tool decides arbitrary prose truth.
- **`cap:workplan-document-model#examples`: accepted.** The complete fenced example uses the real `PROPOSED change:<slug>` syntax and current Change keys (`changes`, section-qualified `affects`, `contract_effect`, and item `claim`). It illustrates a proposal on an implementing capability while retaining the current Contract outside the quote. It is an excerpt, not a complete loadable capability or a change already eligible for completion. The parser/proposal rules and real preview/lifecycle fixtures substantiate those illustrated mechanisms.
- **`cap:workplan-document-model#constraints`: accepted.** The closed profile, flat directory layout, required changed capabilities/affects relationship, consistent rewrite line endings, explicit author-controlled state and tracked-path boundary agree with the actual reader/check/Gate paths. The semantic-truth clause correctly assigns truth to authors and assessors while the runtime enforces structural/state/proposal rules and current accepted affected assessments. Relevant concrete owners include the exact rule inventory and malformed/valid fixtures, mixed-line-ending refusal, nested-document refusal, four-state lifecycle neighbors, and the tracked omit/include/no-checkout/caller-list tests inspected in `queue-document-model-owner-review.md`. The fallback's untracked-file limitation is retained; no process or sandbox guarantee is inferred.
- **`cap:workplan-document-model#explanation`: accepted.** Permanent identity, current text versus Git history, proposals in their eventual document, explicit item outcomes and reconciliation ownership accurately explain the typed model and lifecycle. This is rationale, not an additional automatic prose-truth detector or a claim that every typed record is a graph node. The actual graph supports evidence, assessment and coverage records; the corrected Contract names those types explicitly. Debt create/replace ownership remains separately bound.

## Generated documents

- **`cap:workplan-generated-docs#purpose`: accepted.** Production `generated::analyze` derives mechanical tables and the catalogue from the loaded model; authored prose remains outside that generation. The explanation that people judge prose matches the implementation boundary.
- **`cap:workplan-generated-docs#contract`: accepted.** `generated.rs` has the three closed block kinds and shared analysis for check/sync, deterministic matrix/relationship/catalogue rendering, escaping, placement and line-ending checks. `sync.rs::Workplan::sync` refuses unloaded documents and invalid analysis, validates new-index SPDX, returns complete replacement texts sorted by path and writes nothing. Actual generated fixtures own each kind, placement, malformed markers, cell escaping, catalogue/state ordering, index/SPDX and unchanged authored bytes. Real preview fixtures own selected proposal removal, retained other proposals, indentation/tab/nested-quote/EOL and refusal neighbors. The repaired equivalence is explicitly **generated-block checks** versus no sync edits; unrelated content/binding findings can remain, and unloaded inputs are refused separately. This does not promise clean whole-document checks or atomic publication.
- **`cap:workplan-generated-docs#usage`: accepted.** The shown `Workplan::sync`, separate `Workplan::write` and `preview` calls match the actual public API. The `docs_sync` example is a real caller. Its actual fixture asserts stale `--check` exit 1 and unchanged files, first write's exact file set/bytes, and empty second write/check; separate fixtures own required SPDX only for index creation and invalid root/arguments. A preview slug must exist in the caller's repository; the illustrative name does not imply universal success. The separately specified command-line capability is not folded into this library contract.
- **`cap:workplan-generated-docs#examples`: accepted.** The relationships block example uses the actual open/end marker spelling and illustrates replacement of only the generated region from current graph relationships. Exact relationship rows/link ordering and the header-only empty neighbor are owned by the actual generated fixtures; authored-text preservation has its own byte assertions. The example does not assert an extra generator or arbitrary Markdown rewriting.
- **`cap:workplan-generated-docs#explanation`: accepted.** Restricting generation to computable structured data and retaining authored rationale matches the three production renderers and replacement spans. Stable unchanged bytes and stale-table diagnosis have direct sync/generated owners. Catalogue state/gap derivation is the same Roadmap data used by status. This rationale does not expand generated-only cleanliness to all checks or claim that the separate writer is a sandbox.
