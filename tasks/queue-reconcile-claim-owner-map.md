## Six Constraints: exact ownership and real gaps

1. **No writes except build output / new writes one file.** L's exact-one-file
   new test, impact typed-list snapshot and O `reconcile_writes_nothing` own
   tool writes for their actual fixtures. U `reconcile_writes_nothing_and_prints_the_same_list_twice`
   compares real lifecycle repository snapshots excluding .git. **Current
   universal side-effect wording is too strong:** actual examples/build scripts
   are trusted executable input and can write arbitrary workspace files, not
   only target output. The runner starts them in the workspace without a write
   sandbox. Retain the limitation in Constraints, distinguishing tool-owned
   publication from child effects. An actual bound example writing an owned
   marker, with a no-write example neighbor, is a deterministic proof of that
   boundary. Do not claim a benign fixture snapshot proves child isolation.
2. **No default/common history is a hard error.** U no-default/no-remote/
   no-common-ancestor/outside-worktree/startup tests and E
   `evidence_invalidation_needs_history_only_when_a_claim_names_a_record` are
   actual library history owners. They retain good or no-history-needed
   neighbors. Merge-base extraction is not source currentness; no Git claim
   must be attached to the latter only.
3. **Tense phrases, scope and nonproof semantics.** OT
   `every_phrase_has_a_sentence_that_finds_it_and_every_hit_is_a_phrase` checks
   every phrase with exact output; `near_misses_are_not_hits` checks whole words
   and link destinations; `only_the_marker_name_is_exempt_in_capitals`,
   `only_prose_is_read_and_the_hit_names_its_section_and_line`,
   `generated_blocks_are_not_read`, `a_phrase_continues_over_one_line_break_and_not_over_anything_else`
   prove the stated exclusion and match grammar. These are findings of wording,
   not proof of whether future behavior is built. Keep that honest limitation.
4. **Only direct Git/Cargo children / build effects.** V real example and
   no-test/no-unresolved-example tests prove intended direct process selection.
   The source Executor chooses only resolved bindings. No claim of transitive
   process restriction is possible: Cargo/executed examples may start children.
   If “one process besides git” means one program category, say so; it cannot
   mean one spawn, since build/list/run phases can use several Cargo invocations.
   Child file effects need the same retained boundary as Constraint 1.
5. **No document text becomes argv except typed fields.** U real executable
   argv stub checks end-of-options, fixed dash options, commit:path as one word,
   root cwd/C locale; Git typed RefName/Commit/SourcePath constructors and
   executor resolved Binding path provide the production boundary. Keep exact
   hostile-path/default-ref and unresolved-example fixtures. To directly prove
   hostile prose stays out, include a marked document string plus recorded exact
   Git/Cargo receipts with no such argument and a valid ordinary neighbor. A
   substring search of command Display alone is not an argv ownership proof.
6. **Obligation gives section/evidence rather than generic advice.** OT exact
   order/rendering and `the_evidence_names_the_thing_it_is_about_in_parentheses`,
   O exact Case::run assertions and CLI exact lines are meaningful ownership.
   Some genuine obligations are document/item scoped, and wording itself says
   those parts earlier. “It names the section” must mean its actual applicable
   part; don't overstate every obligation as a capability section when item or
   index obligations have no such section.
