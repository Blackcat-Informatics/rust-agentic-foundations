# Execution trust and publication boundaries

The operational limits remain judged Constraints. Their explanatory detail is
also retained in Explanation; relocating a real limit alone is not adoption.

`verify::selected_cargo_output_is_trusted_but_an_empty_list_is_refused` uses the
actual SystemRunner path. Ordinary Cargo runs the fixture's authored panic and
fails. A selected executable that emits a matching one-entry list and positive
result instead passes. An empty-list neighbor is Unresolved; an exact receipt
proves no run invocation follows it. This demonstrates selected-executable output
trust, not an unexecuted libtest-capture spoofing technique. The focused log
`raw/queue-trusted-runner-proof.log` returned terminal exit 0. The Constraints
marker additionally owns actual two-entry/wrong-name refusal tests and the native
count spelling/overflow test.

The second-judgment clause says it re-evaluates conditions and binding keys; it
does not promise to reject every harmless prose edit. Actual existing tests own
newly failing conditions, added bindings and record-link replacement during
execution.

`sync::write_publishes_the_computed_snapshot_without_comparing_later_authored_edits`
computes a real SyncReport from on-disk documents, replaces authored text after
report computation, and invokes actual Workplan::write with the original report.
The public writer overwrites the newer bytes with its exact computed snapshot;
the ordinary unedited neighbor also succeeds. The strengthened current fixture
checks the newer authored text itself still loads and produces a report retaining
that prose. This is the actual publication implementation called by completion's
second evaluation. It does not claim a post-judgment symlink race was executed;
the removal's path-based behavior is separately source-inspected.

The initial snapshot proof passed in `raw/queue-publication-snapshot-proof.log`.
The stronger current proof is recorded separately in
`raw/queue-publication-snapshot-current.log` and passed with terminal exit 0.
Independent bounded prose/source review is in
`tasks/queue-completion-constraints-proof-review.md` and its subsequent recheck.
No delivered-state adoption, lifecycle completion or full-gate result is claimed.
