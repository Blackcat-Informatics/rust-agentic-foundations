# Authority-qualified loader increment

Read-only source review of the current, not yet compiled delta. No concrete authority-collapse or native admission defect found in this increment. No builds or product edits performed. This is physical multi-source loading, not locked dependency/provider authentication.

- `Workspace::load_with` constructs ordinary authority-zero roots and delegates to the same `load_from` implementation. Empty roots still refuse; explicit qualified roots enter discovery unchanged. Discovery's found manifest map, directory selector, Workspace files and walker keys retain RelPath authority. Target Context uses each package's actual ID and qualified manifest/directory. The package-name selector keeps duplicate display names and makes name-only resolution ambiguous rather than picking a source.
- Discovery names compare the same `(authority, name)` tuple used for insertion. Same-source duplicate names still refuse; equal names in different sources are admitted. Overlapping roots reaching one qualified manifest remain one package.
- `workspace_of` starts at the actual qualified package directory and retains authority through parent/join and both workspace/member caches. Workspace-inherited paths therefore stay within that source. Path dependencies join their actual declaration base, pass authority-preserving tidy, then search the full qualified directory selector. No name-only dependency destination or directory-text-only match was found in these inspected paths.
- `remember_name` resumes both ItemAdmission and native Memory at the same retained `name_bytes`, which covers the retained key strings and OrderedTable backing. String growth and table insertion happen under that original account before retention. The surviving native total is saved after insertion. Recreating only the adapter does not reset its live grant or cumulative ItemBytes. Errors preserve the first typed admission failure or native Storage cause. The table's inline header is separately charged in discover. This differs correctly from restarting Memory at zero around a populated table.

The new actual fixture inspects two equal-name packages at equal relative paths with distinct definitions: ambiguous name query, exact package-ID query, foreign definition absent, source text selected through Item.file, authority correspondence and distinct source_key. Its exact/one-less ItemBytes assertions cover whole-load acceptance and typed refusal. They do not isolate the names account: a one-less whole-load failure can occur after discovery, so this test alone would not detect dropping a discovery-specific charge.

Useful bounded additional assertion ownership: an internal names-table test that inserts enough distinct same-authority names to grow populated native backing, checks the original cumulative grant and original native refusal on a failing subsequent insertion; and a real two-authority workspace fixture with identical package/directory names but different inherited editions and path-dependency definitions. The current no-dependency fixture cannot itself substantiate those metadata paths, though the source trace above found no collapse. Retain existing duplicate-name-in-one-source and overlapping-root tests rather than weakening those refusals.
