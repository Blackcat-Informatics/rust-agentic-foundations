# Preserved RDF kernel: preparation review

Read-only source review of the uncommitted `raf-rdf` skeleton at issue 16 HEAD `07169f5`. No product files changed and no build, suite, or executable probe ran for this review. Findings below are deductions from the inspected implementation, not runtime qualification. Census migration and workplan adapters are not implemented yet.

## Actionable findings

1. **Absolute IRI construction does not validate an absolute RDF IRI.** `term.rs:21–31` checks a scheme, `IRIREF` forbidden characters, and percent-triplet shape, but not RFC 3987 components. For example, `https://[`, `urn:a[b`, and `urn:a#b#c` pass those checks. They can become predicates, datatypes, external objects, or quoted-statement subjects; the writer faithfully emits them and the reader uses the same constructor. Exact canonical comparison therefore cannot repair this semantic gap. `purrdf-lex` explicitly supplies lexical terminals and escaping, not the complete IRI parser. The cached `purrdf-iri` 3.0.1 public `parse` API validates RFC 3987 components and exposes `scheme()` without rewriting the spelling. Evaluate that concrete dependency, or a comparably complete existing parser, and require an absolute scheme. Do not introduce a second home-grown IRI grammar. Preserve lexical identity rather than invoking normalization. Cover invalid authority/brackets, a second fragment delimiter, forbidden Unicode/control scalars, and valid Unicode, IPv6, URN, and percent-encoded neighbors in construction and both readers.

2. **The supposedly language-free literal model admits language datatypes without their required language metadata.** `Atom::Literal` is public; `Atom::validate` at `term.rs:102–106` only refuses local datatypes. It permits `rdf:langString` and `rdf:dirLangString`, while the model has no language tag or base direction and the writer always calls `write_literal(..., None, None, ...)`. That cannot represent those RDF literal kinds. Refuse both datatypes in the shared validation path, including inside triple terms, unless the profile is deliberately expanded with the actual missing fields. The agreed closed profile excludes language-tagged literals, so refusal is the smaller correction. Pair those refusals with `xsd:string` and an ordinary explicit datatype as valid neighbors. Do not conflate this structural restriction with consumer-owned validation of numeric lexical values.

## Essential checkpoint tests

- Construct a graph with a root, multiple named nodes, deliberately shuffled insertion order, strings with quotes/backslashes/newlines/NUL/non-ASCII, explicit integer/boolean/custom datatypes, external IRIs, and a named reifier pointing to a depth-one triple term. Assert deterministic bytes, both-format round trips to equal internal graphs, equal snapshot identities, and the same identity after changing only output format. Changing graph content must change the identity. Include root and fragment references inside triple terms.
- Replay both emitted formats through an independent RDF 1.2 parser and compare its absolute ground triples, including the typed literals and triple terms. Retain exact fixture bytes, parser version, replay command, and expected N-Triples. The N-Triples root must be emitted first even when fragments were inserted first. This checks actual graph equivalence, rather than trusting the kernel's two mutually dependent readers.
- Exercise missing root, duplicate triple, dangling ordinary object, dangling quoted subject/object, foreign top-level subject, relative ordinary/quoted predicate, relative datatype, literal subject, and a nested triple term, each with a valid neighboring graph. Existing code appears to enforce the owned-reference and role restrictions, but code presence is not execution evidence.
- Exercise N-Triples ownership boundaries: exact root and `root#fragment` normalize; `root + "suffix"`, another digest's fragment, and a malformed own fragment must not become owned nodes. A prefix-sharing external object remains external. Relative IRIs are refused in N-Triples.
- Exercise exact canonical refusals while preserving semantic validity: CRLF, missing final LF, extra final LF, leading whitespace, reordered triples, alternate UCHAR spelling, explicit `xsd:string`, and alternate spacing. Assert the first differing line for newline cases. Exercise malformed/truncated UCHAR, surrogate/out-of-range escapes, invalid ECHAR, and escaped IRI characters. Retain a canonical valid neighbor for each family.
- Exercise BASE namespace, lowercase full-digest width, digest tampering, empty input, and selecting the wrong format. Consumer adapters must separately reject an unknown report profile or vocabulary/shape; the generic kernel intentionally does not know those closed registries.
- Migrate the actual census baseline/index writer and reader with an explicit report-profile bump, preserving all current shape/cardinality/semantic refusals, full fingerprints, start-byte uniqueness, injective minting, named match provenance, read budgets, and independent pins. Keep normal-form hash bytes unchanged. Do not declare the shared foundation complete from kernel-only fixtures.
- Implement a real typed workplan Finding/coverage consumer before API qualification. Check nested fields and provenance against a documented closed registry and exercise both formats and refusal neighbors. The later command migration must replace both `Record` JSON fields and `Rendered` JSON routes, without flattening values into messages.

## Dependency and identity notes affecting implementation

The inspected writer does use one fixed normalized Turtle spelling as the hash preimage, with the BASE line excluded; N-Triples expands owned root/fragments using that same digest. The reader verifies the same preimage after owned-node normalization and compares the selected exact canonical bytes. `BTreeSet` iteration avoids comparator string allocations and the parser does not clone a second graph for formatting. These source observations need the tests above before any qualification claim.

The earlier path proposal's reserved-self-token/framing paragraph is superseded by the accepted simpler normalized-body law implemented here. Document the final law and explicit census report-profile migration; do not implement both identity paths. This review does not propose changing that law.

Inspected `purrdf-lex` 3.0.1 sources: `term_syntax` supplies exact triple-term delimiters and canonical literal/IRI writing, including elided `xsd:string`; `terminals` supplies UCHAR/ECHAR and raw `IRIREF` lexical restrictions. `percent::decode` also allocates decoded text and rejects non-UTF-8 decoded octets, so it is not a drop-in percent-triplet validator for arbitrary legal IRI percent octets. If complete IRI validation subsumes the skeleton's `percent_valid`, remove that redundant helper rather than decoding/re-encoding IRIs. Continue using the existing census `percent::encode` minting path for injective application identifiers.

No result here establishes full issue 40 acceptance, sole-policy default adoption for issues 16 and 37, portable census acceptance under issue 46, or completion of the first-consumer checkpoint.
