## Full-file token overlay design check

Lexing the whole file and overlaying independently computed naming forms can extend coverage without changing fingerprints, provided the original normalizer/Form inputs remain untouched. The mixed search Form is pattern-specific output, not a replacement NF or a newly hashable canonical form. Shift every retained Place byte range (leaf plus both group delimiters) by slice.offset exactly once; source.first_line already gives absolute lines. Replace only an exact whole-node interval inside the matching delimiter context; preserve surrounding function-body braces and initializer punctuation. Missing/misaligned boundaries must refuse rather than fall back to a partly overlaid tree. Original file MAX_NESTING bounds traversal depth; actual scans/copies/frontiers must still participate in matching/resource limits.

Two semantic decisions remain before calling one-tree coverage equivalent to existing per-unit matching:

- Nested unit ranges can overlap. leading_forms of an outer body already renames a nested function and its body using that outer body's binding population. Overlaying the nested body with its independently normalized form can change those tokens again. One tree cannot represent both exact normalization contexts simultaneously. A coherent small option is to overlay only outermost disjoint unit ranges for the whole-file search, retaining independent nested-unit searches for their original contexts and deduplicating physical hit positions. Alternatively define and test a different explicit context policy; do not silently claim exact preservation of both.
- The pattern itself currently runs through leading_forms as a body fragment. For example a tokens pattern containing `fn banned() {}` has its declared function name treated as a local binder and renamed; a full-file top-level `fn banned() {}` deliberately left literal will not match that normalized pattern. Whole-file coverage therefore needs a matching pattern-context policy too, not just a source overlay. Preserve literal declaration names with a deliberately paired literal/template context, or otherwise state/test the intended rule. Do not globally rename file-level items merely to satisfy the comparison; that would destroy their literal identity.

Required close neighbors are top-level declarations/macros, empty and braced initializers, two independent functions with different parameter populations, and a nested function whose outer/local binder numbering differs. Existing fingerprints/goldens must remain unchanged. This is bounded design advice, not acceptance of an implementation: current production still performs per-unit token searches.

## Implemented overlay source recheck

Read the actual source.rs sequential overlay and its production call. No concrete span/group corruption found. slice_source offsets select body interiors or complete initializer expressions; shifted leaf/open/close byte ranges are absolute once, while the preexisting first_line already preserves absolute lines. The containing body delimiter remains around the normalized interior. An initializer consisting of a whole group is replaced with that normalized group. Whitespace/comment-only and empty interiors have empty replacement nodes and need no source token to consume. Nonempty leftovers and partial token overlap refuse explicitly.

The sorted ranges select outermost contexts. Source Fn extraction does not emit nested block functions as independent ItemFacts, so those local functions remain in the original outer body's exact naming population; the earlier nested-independent-unit concern is not a demonstrated defect on this index. The overlay does not globally rename file declarations or feed a changed Form back into NF/hash production. It invokes existing Form::lex and leading_forms; there is no second lexical/normalization implementation. shift/overlay recursion uses the same lexer-bounded delimiter depth. No new runtime or golden pass is inferred by this review.

The existing pattern-side declaration boundary remains explicit: pattern compilation treats `fn banned() {}` as a body fragment and renames its local-function binder, whereas a file-level declaration keeps banned literal. Thus a specific global declaration pattern needs a paired context policy/fixture before claiming that form matches; the remedy is not a whole-file NF change. The implemented file-level macro fixture does establish a separate useful coverage boundary. This note does not demand independent normalization of local functions or a generic whole-file canonicalizer.
