# Path matcher interface on delivered Source

Read-only interface analysis on the delivered base. Inspected Workspace, Item/ImplBlock/Reach, resolve, reach internals and the pattern contract. No builds, product edits or dependency/upstream changes. This does not require completion of the broad configuration/std/macro work.

## Available seams

- `Workspace::files` / `file`: exact source bytes plus `SourceFile.reached`. Every Reach gives `target`, the file-root `module_path`, test flag and path predicate. A shared file must be considered under every relevant reach, not only SourceFile.package or the canonical Census Unit symbol.
- `Workspace::item_at(file, byte)`: innermost indexed source owners, including alternative reaches. It does not return the reading module. `Item.path` cannot safely be truncated to obtain that module: methods are under their self type, trait members under the trait, unresolved impl paths have special spelling, and macro-export names can be relocated to the crate root.
- `Workspace::impls` / `impl_block`: actual ImplBlock.module, target and physical span give the module for impl-owned occurrences. File Reach.module_path plus a syntax visitor's inline-module stack gives ordinary module context, but is not by itself a resolver or a complete local-scope model.
- `Workspace::resolve_from_in(module, path, Namespace)` follows actual indexed workspace module imports/reexports and enforces the reading module's accessibility. It is explicitly a USE-path API, internally `Heads::Use { test: false, own: None }`. It is not a general expression/type occurrence API. Edition-2015 use roots, test/dev eligibility and code visibility differ from `Heads::Code`.
- Canonical `resolve_in` resolves the pattern's workspace item in its intended namespace. Success provides a canonical path and nonempty actual ItemId sites, with target-aware ambiguity checked by the shared resolver. Compare actual sites/defining targets, not just strings. Call uses Value; macro uses Macro; type uses Type. A general path matcher must preserve actual syntax namespace rather than accepting the first successful namespace indiscriminately.

## Concrete gaps

There is no public item-to-reading-module or target-qualified code-occurrence resolver on this base. The exact owning-module computation already exists privately in `reach.rs::Walk::new`/Home: module defs, impl member homes and trait member homes. Factor/reuse it if exposing a narrow Source-owned context; do not reconstruct semantic ownership by chopping Item.path in Census. Public resolve_from takes a textual module only and can be ambiguous for equal crate/module paths in different targets; occurrence.target must remain authoritative.

The index describes module-level bindings, not lexical local/parameter/generic/block-use scopes. A local callable `fn banned() {} fn run(banned: fn()) { banned() }` must not resolve to the module function. Likewise a generic parameter can shadow an imported type. A block `use other::banned` must not be read through the outer module's banned binding. Existing `reachable` is not an occurrence oracle: it returns aggregate edges, not per-occurrence proof, and `tests/reachability.rs::a_method_call_a_field_a_lifetime_and_a_local_name_no_item_and_a_path_prefix_names_its_type` expressly records a local label being read as the same-named function. Do not reuse that approximation as pattern identity evidence.

Public Resolution has no external/std-only success representation. Its sites are never empty. NotFound deliberately conflates unindexed dependency items, macro expansions, misspellings and other absent paths. Neither its error text nor a written `std::`/dependency prefix authenticates a definition; no public API currently exposes an alias-expanded external canonical identity. Some foreign impl keys can name indexed implementation members, but are not external definition provenance. Grounded dependency/reference/provider matching must use the active Source foundation when integrated.

## Small coherent integration

Keep syntax-kind classification, actual occurrence spans and rule reporting in Census's existing bounded parse. Add a narrow Source-owned code-query seam rather than another Census import resolver: an opaque context selected from the actual owning ItemId/physical offset (including target, module, test state and lexical namespace shadows), then resolution of one written path in one namespace through the existing shared walk/conclude with `Heads::Code`. Reuse the existing internal module-home calculation and walk bodies. Account query scratch/work against the original Source owner and propagate typed failures; never turn allocation/budget failure into NotFound. No complete Cargo resolver, cfg evaluator or macro expansion is implied by this seam.

Lexical binding classification can be a bounded syntax observation shared by Source's occurrence query; it must cover parameters/pattern bindings, let initializer-before-binding order, nested blocks/closures, generic type parameters and block item/import scopes. Known shadowed locals are nonmatches to module-definition patterns. Unknown/unsupported lexical imports or self/qualified forms need an explicit actionable unsupported result, not an outer-scope fallback. This is a concrete prerequisite to claiming those four matchers preserve shadowing; adding only a code-from-module wrapper is insufficient.

Resolve an indexed pattern and each supported occurrence using the shared resolver, then match actual definition identity with namespace and source reach retained. Deduplicate findings by existing physical owner after considering all reaches. Ambiguous/cyclic/unsupported resolution must remain visible. An unindexed external/std pattern cannot currently be advertised as alias-resolved or grounded; reject that requested semantic matching actionably until the actual dependency Source binding is supplied. A separately declared written-syntax-only rule could match literal spelling, but silently substituting it for this resolver-backed contract would be a scope change.

Minimum meaningful neighboring fixtures: workspace reexport and renamed import hit; same final spelling bound to another definition nonhit; parameter/local/generic shadow nonhit; block import to the intended definition versus another definition; inline/external/shared-file module contexts; library versus dev/test contexts; Value/Type/Macro same-name distinction; unresolved dependency/std request refusal beside indexed workspace success. Token and literal-regex execution can proceed through their existing independent semantics while these source-query gaps are resolved; no incomplete path matcher should be labelled executed by declaration alone.
