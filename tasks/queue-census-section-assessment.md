# Census section judgments

The seven current production contexts are retained in
`raw/assessment-census-cli-current/`, captured in session 44590 (exit 0).
The individual verdicts below are accepted. Publication must separately compare
every context before any write, and currency is a separate result. This does not
assess the source-index capability or establish complete portable-core acceptance.

- Purpose: the input is a supplied Tree and the results depend on admitted source
  and owned values. The text now promises equal selected forms produce equal
  fingerprints, rather than implying semantic equivalence of arbitrary equal
  algorithms. The core starts no processes or filesystem reads of its own;
  supplied Tree effects remain the caller's boundary.
- Contract: source and assertion review covers parameter/local renaming, retained
  item/field names, value adapters, fixed literal tier and shim eligibility;
  complete digest identity and separate human abbreviation; unchanged u32-LE token
  framing; caller options and version gating; real source units and shared-target
  ownership; deterministic grouping and job classification. Native hash/scalar
  replacements retain the golden normal form rather than creating a new policy.
  Old external-blake3 feature wording has been corrected against the actual
  pinned zero-runtime-dependency native hash manifest. Closed report profile 2
  reads both formats with the same declared NF version, complete fingerprint and
  byte-start identities, domain/cardinality refusals and named reifiers. The
  shared profile owns serialization; Census owns its domain shape. Report profile
  migration is distinct from unchanged fingerprint bytes.
- Usage: the actual baseline example, single-source normalizer, Tree load, job
  matching, baseline/index conversion and explicit version gate have their real
  public paths. Designed CLI/ledger consumers are identified as designed. The
  on-demand literal-value introspection reuses production passes without adding
  tuning defaults or analysis allocation to ordinary loads.
- Examples: the baseline/index examples remain exact pinned canonical output;
  table/constant and match rows retain real full identities and byte positions.
  Absolute and relative directory behavior is an explicit source-root spelling
  rule. These examples do not claim that a future Census CLI already exists.
- Constraints: written-source/macro limits, whole-body name overapproximation,
  initializer-only metadata, lossy byte strings, size/tier boundaries and hash
  collision assumptions are actual limitations. Source parses own signature
  facts; Census normalizes only bounded bodies. A fresh native worker releases
  collection TLS on success/error/panic and preserves caller spans and panic
  payload, without adding Tree Sync/Send bounds. The finite ordinal/teardown
  observations are not RSS or byte-bound measurements, and spawn failure was not
  forced by exhausting host threads. Standalone lexer storage and complete
  portable-core/wasm acceptance remain explicitly unproved here.
- Explanation: the fixed corpus policy cites actual counted/labelled observations
  and limitations, not real-source precision without labels. The native collection
  lifetime and source-target dependency explain current implementation decisions;
  they do not waive portable-core requirements. Full hash equality relies on
  BLAKE3 collision resistance rather than obsolete truncated-key collision guards.
- Verification: actual native caller receipts include all 29 form tests and 31
  unit tests in `queue-native-text-census-forms.log` and
  `queue-native-text-census-units.log`; the selected real worker boundary and

  scalar, report, registry and pin receipts retain their source-snapshot scopes
