# Path matcher implementation review

Bounded source review of paths.rs, paths/scopes.rs, paths/visit.rs, shared syntax Names and Source CodeResolver refinements. No builds/tests or product edits. Parent reports an earlier 43-case Gate pass; current lint/refinements remain owner-qualified separately. The pattern capability and owner's workspace-alias direction govern this review; full std/dependency authentication is not required for a syntax ban.

## Concrete findings

1. **A block import must remain authoritative even when unindexed.** For `fn drop_it() {} fn consumer(){ use std::mem::drop as drop_it; drop_it(1); }`, the block expansion queries std::mem::drop and gets NotFound. matches then queries raw drop_it in the module and resolves the shadowed module function. This falsely matches an indexed demo::drop_it pattern and misses the unindexed syntax pattern std::mem::drop. Once a block alias binds the head, use its supported expanded observation; do not fall back to the overridden raw module binding. Its syntax spelling is still not provider identity.

2. **A pattern identifier can denote a constant, not a new local.** Scopes::bind treats every PatIdent as a binding. In `const BANNED:u8=1; fn run(x:u8){ match x { BANNED => { let _=BANNED; }, _=>{} } }`, the arm's BANNED is a constant pattern. The new local-set entry suppresses the real constant path inside that arm. The exported Source binding callback explicitly describes syntax rather than constant-resolution proof. Distinguish the actual constant-pattern candidate through Source before classifying an ambiguous arm identifier as a shadow; preserve a genuine binding with a different local name as the neighbor.

3. **Valid macro statement/repetition syntax is silently skipped.** visit_macro parses only a comma-separated Expr list. `vec![std::mem::drop(1); 2]` is valid written Rust macro input containing the banned call, but fails that parser and the visitor traverses no expression. A bounded existing syn statement-body observation can cover this actual case without interpreting arbitrary macro DSL. Do not silently claim all macro-argument path coverage from the expression-list fixture alone.

4. **UseTree paths are not currently occurrences.** There is no visit_item_use/use-tree path observation; Syn's default UseTree visitor visits identifiers, not ExprPath/TypePath. A general path pattern for std::time::Instant therefore misses an otherwise unused `use std::time::Instant as Clock;`. Handle actual reconstructed import paths, retaining grouped/self/rename/global spelling and declaration reading context; aliases are declarations, not uses of their bound local name.

5. **Qualified-self forms are silently skipped.** Both expression and type visitors require qself.is_none(). A call `<S as demo::Trait>::banned()` and the trait portion of `<S as demo::Trait>::Assoc` are not observed. The QSelf type may be visited independently, but does not cover the qualified callee/trait path. Support the written qualification using actual syntax and available shared lookup, or explicitly refuse unsupported requested semantic forms. A blanket silent nonmatch is not complete call/path/type execution. This does not request type inference, trait dispatch proof or full Source dependency loading.
