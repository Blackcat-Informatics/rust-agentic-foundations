## Findings

### Blocking

1. **Syntax errors always report line 1.** src/parse.rs:50-56. `syn::Error` is built on the parse thread and returned across `join()`; `syn::Error` stores its span in a thread-bound cell, so on the caller's thread `error.span().start().line` falls back to `Span::call_site()`, which is line 1. Probe: `parse_source(.., "fn ok() {}\n\nfn 1 {}\n")` gives `src/a.rs:1: syntax error: expected identifier` (the error is on line 3), and a `struct S { x: }` on line 5 also gives line 1. `LoadError.line` is documented as "the 1-based line of the failure", so this is a silently wrong value. It also contradicts C3's intent that proc-macro2 data never crosses the parse thread (here a `syn::Error` does). The test hid it: tests/prescan_budgets.rs:176-186 asserts only `error.line.is_some()`. Fix: compute `message` and `line` inside the worker closure (`syn::parse_file(text).map_err(|e| (e.to_string(), e.span().start().line))`) and return plain data; strengthen the test to assert the exact line (and a lexer-level failure such as an unbalanced `{`, which currently also reports 1).

2. **The harness counts any non-zero exit as an allowed "abort".** tests/support/child.rs:121-126 (`(code, _) => Outcome::Aborted`) and :156 (`Aborted => None`). A child that panics (exit 101), an unknown selector (`text_of` panics at overflow_harness.rs:44 and corpus_replay.rs:31-33), exit 3 or 4 without a result line, or a missing corpus file all fall into `Aborted` and pass. A panic in the pre-scan on a corpus file, which the Contract says never happens ("a typed error and not a panic"), would therefore pass the replay gate in both profiles. The plan's "non-zero status" is satisfied literally, but the gate's purpose is to catch regressions. Fix: classify `Aborted` only for death by signal (`ExitStatusExt::signal()`), the Windows stack-overflow status, or stderr containing `has overflowed its stack`; make a panic (101) or an exit-3/4 without a line `Failed`. Add a fixture for a child that panics.

### Non-blocking

3. **Contract and SECURITY do not say what is measured: 10 of the 11 composite/uncounted fixtures abort the process today.** docs/capabilities/source-index.md:126-131 and SECURITY.md:66-76 describe the mechanism ("unlikely", "residual overflow aborts the run") and the three outcomes, which is truthful, but a reader is not told that the committed composite and uncounted shapes (a 140 KB `return return ...` file) reproducibly kill the process. "Make ... stack overflow unlikely" is generous beside that. Add one sentence naming it, and keep the already-present sentence that the fuzz run cuts to 4096 bytes (source-index.md:271-274, present and honest). Also source-index.md:129 says a debug build costs "about 16 KiB of stack per level" while tests/overflow_harness.rs:15-18 measures about 8800 bytes per `return` level in debug; state which shape the 16 KiB belongs to or reconcile.

4. **The `else if` counter is evadable, and the evasion is not disclosed.** prescan.rs:109-134. A `}` that closes a condition block resets the chain: `if a {} else if {true} {} else if {true} {} ...` (20000 links) is admitted (probe: parsed, 1 item; it did not overflow at that size, debug). Lifetimes (`&'a &'a ...`) likewise reset the prefix run. These fall under the documented class "some recursive shapes are counted by no budget", but the Contract defines the `else if` counter as "each `else` directly after the `}` of the previous block" without saying a block condition restarts the count. Add a fixture or a sentence; ideally an uncounted-shape corpus entry for the `{true}` form.

5. **Thread-name assertion matches two substrings.** tests/overflow_harness.rs:106-107. Acceptable: the runtime prints `thread 'NAME' (id) has overflowed its stack`, so the id forces two parts. Tightening it to one line check (a stderr line starting `thread 'overflow_return.rs'` and ending `has overflowed its stack`) costs nothing and avoids matching an unrelated line.

6. **`LoadErrorKind::Spawn` is not in C2's kind list.** error.rs; C2 names `Tree`, `Budget`, `Syntax`, then later kinds. It is reasonable (the plan's spawn failure must be typed, and the type is `#[non_exhaustive]`), but C2 and the Contract text should mention it when Task 9 reconciles. Boxing `Tree(Box<TreeError>)` and `origin: Option<Box<Origin>>` is acceptable: it keeps `LoadError` small for `Result` and `source()` still returns the inner error.

7. **Cargo emits a manifest warning on every fuzz invocation.** Seen in the `make fuzz` log: "binary `parse_source` should have a kebab-case name" (`cargo::non_kebab_case_bins`). cargo-fuzz requires the target name to match, and `clippy -D warnings` does not cover cargo's own warnings, so it is harmless to the gate but noisy; note it or silence it in a way that does not weaken a lint.

8. **AGENTS.md "Workspace lints" (section 3) does not mention that `fuzz/Cargo.toml` mirrors the root tables and that `repo_gates` enforces it,** nor that `fuzz/deny.toml` must equal `deny.toml` plus the NCSA exception. The gate lists are otherwise consistent (see below). One line would close it.

9. **Cosmetic:** CHANGELOG.md Gates entry has one line well over 80 columns ("Windows targets, the licence digests ... on a checkout of"); Makefile line 57 comment likewise. CONTRIBUTING.md:66-68 breaks mid-sentence ("on" then newline).
