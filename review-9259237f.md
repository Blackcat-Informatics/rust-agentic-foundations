## Findings

### 1. REQUIRED: artifact inputs of model-associated evidence are digested as Rust symbols, which breaks `assess`

`crates/raf-workplan/src/assessment.rs:921-923` (unchanged by the diff, but its premise
is broken by the diff):

```rust
if let Some(record) = record {
    for input in &record.value().inputs {
        self.model_symbol_input(&input.name, named, inputs);
    }
}
```

This loop was written when an evidence record could hold only `symbol` inputs. It now
also receives `artifact` rows. For every evidence record that a capability's architecture
model associates with a scenario or step (`ArchitectureModel::evidence`, "Independent
execution records associated with scenarios and steps", which is exactly where a
measurement or log artifact belongs), the artifact path, such as `.stage/run/bench.txt`,
is passed to `Digest::symbol`. It becomes an `(InputKind::Symbol, path)` row that never
resolves. As a result:

- `assess` of any section of that capability refuses with `AssessError::SymbolUnresolved`
  (the match at `assessment.rs:1087-1089`).
- The assessment currency treats the bogus row as "an input now and was not then", so
  `assessment-stale` can never be cleared.

The new `unreachable!` comment at `assessment.rs:1090-1095` claims that `inputs_now`
builds rows of section, declaration, symbol and record kinds only. The claim holds only
because this path files the artifact under the wrong kind.

Fix: filter that loop to `InputKind::Symbol`. The evidence record's own `Record` digest
already covers its artifact rows' digests, and `evidence-stale` covers the file itself.
Add a negative fixture: a model-associated evidence record with an artifact row, assessed
beside a neighbour record without one.

### 2. REQUIRED: the strict (complete check) and diagram artifact path has no test, yet the docs claim it

`stale_inputs` (`crates/raf-workplan/src/digest.rs:431-458`) gained an artifact arm. Its
only callers are the strict measured-evidence currency (`strict.rs:281`) and diagram
verification fields (`diagram/semantic.rs:667`). The reconcile path does not use it:
`obligation/trace.rs` keeps its own copy. None of the new tests reaches that arm.
`the_profile_refuses_an_artifact_path_that_escapes_the_workspace` calls `plan.check()`,
but its record has no measures and its capability requires no measured evidence.

Even so, `docs/capabilities/workplan-evidence-claims.md` (the Artifact inputs paragraph)
states "a stale input is the `evidence-stale` obligation, and the complete check names
it", and binds that paragraph to four tests, none of which runs the complete-check path.

Fix: extend the existing
`strict::a_failing_or_stale_measured_record_does_not_satisfy_the_requirement` with a
measured record whose artifact changed. It must yield `measured-evidence-missing` naming
the path, beside the same record with the matching file, which satisfies the requirement.
Then add that test to the paragraph's `raf:tested-by`.

### 3. OPTIONAL: the `Tree::read_bytes` default refusal leaves the Git trees byte-blind

The provided method refuses with `Unsupported`. `PinnedGitTree`, `RegistryArchiveTree`
and the workplan's own `BaseTree` (`lifecycle/touched.rs:739`) hold blob bytes but do not
override it. `CommittedGitTree::read_bytes` "delegates" to `PinnedGitTree`, which uses
the default, so it behaves exactly as the default would. Meanwhile
`docs/capabilities/source-index.md` lists the committed Git tree among the trees that
"implement or delegate" byte reads. This is not a contract gap, because the issue is
about the worktree. Still, making the method required, or stating that the committed Git
tree refuses, would make the contract clearer. As it stands, `review::at_revision` loads
a plan through `BaseTree` and records an `Unsupported` result for every artifact, though
nothing there reads it.

### 4. OPTIONAL: every tree error becomes `evidence-stale`, including I/O and `Unsupported`

`artifact.rs` maps every `TreeError` to `InputMoved::Unresolved`. The symbol path, by
contrast, separates query refusals (`is_query_refusal`) so that "reporting it as a changed
input would hide the cause". The reason text is kept, so the error is not silent. But the
strict fix text ("record an evidence record whose `for` lists this capability with ...
current input digests") misdirects the author on a permission or I/O error. A typed
refusal for errors other than not-found, not-regular, too-large and outside-root would
match the symbol design. The docs do state the current behaviour.

### 5. OPTIONAL: test overlap and stale test comments

- `obligations::the_profile_refuses_an_artifact_path_that_escapes_the_workspace` repeats
  the okf records test (`../outside.txt` and `/etc/passwd`) through disk scratch. Only
  `a/../../b` is new.
- The doc comment of `artifact_inputs_accept_repository_relative_paths_and_refuse_escapes`
  says "an assessment or a review with the kind is refused", but only the assessment is
  exercised. Review refusal is pre-existing behaviour.
- `crates/raf-okf/tests/records.rs:407` still says "Evidence is made against symbols only."

### 6. OPTIONAL: the commit message overstates the sharing

The commit message says "The currency of symbol and artifact inputs is computed once and
shared by the reconcile, strict and diagram paths." Artifact digests are computed once.
Symbol currency is not: `trace.rs` keeps its own `Digest::symbol` cache, separate from
`stale_inputs`, and that duplication is how finding 2 went untested. Reword it at the next
amend.

### 7. OPTIONAL: the non-regular and size-limit claims are proven only by composition

The docs say that a non-regular file and a file over 256 MiB leave the input stale. Each
part is proven separately: the `raf-source` tests prove that `read_bytes` refuses both,
and the artifact code maps every refusal to stale, which the not-found and outside-root
tests demonstrate. No workplan test places a directory at an artifact path. That would be
a cheap direct check.
